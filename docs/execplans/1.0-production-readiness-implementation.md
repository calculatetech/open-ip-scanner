# Deliver a production-ready Open IP Scanner 1.0

This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must be kept up to date as work proceeds.

This plan is maintained in accordance with `.agent/PLANS.md` from the repository root. A contributor must be able to resume from this file and the working tree alone. Keep the plan self-contained, update it at every material stopping point, and replace the single revision note at the bottom when the plan changes.

## Purpose / Big Picture

Open IP Scanner 0.2.0 builds and can scan a local IPv4 network, but the production-readiness audit found unsafe worker ownership, unbounded cancellation, unreliable mDNS enrichment, misleading service evidence, no automated quality gate, and invalid release packaging. The goal of this plan is to turn that prototype into a dependable 1.0 desktop application for Linux x86-64 and IPv4 networks.

After this work, a user can select an adapter, scan as many as 4,096 IPv4 targets, stop or close without a frozen window, see where hostnames and service claims came from, obtain an Avahi `.local` reverse name when one is available on the selected interface, and export results without spreadsheet-injection or silent write failures. A maintainer can build and test the application from a clean checkout with one command, produce a policy-clean and hardened Debian-family package, and verify its software bill of materials and signed GitHub provenance.

The visible demonstration is a controlled scan fixture that publishes `fixture.local` through Avahi on a private test interface. The completed application must show the plain hostname in the table and its compact mDNS provenance in Details, cancel the scan in less than two seconds, preserve a responsive 4,096-row table, and pass the full release gate described below.

## Surprises & Discoveries

- Observation: Almost all behavior currently lives in a 3,534-line `ScannerWindow` implementation, including parsing, scheduling, process execution, networking, persistence, export, and rendering.
  Evidence: `src/scannerwindow.cpp` and `src/scannerwindow.h` contain the entire scan path and UI state; CMake builds only one executable.

- Observation: The current application successfully invokes Avahi and receives the local `.local` answer, but an earlier preliminary hostname prevents the better answer from replacing it.
  Evidence: The audit trace captured `avahi-resolve-address -4 10.10.30.34` writing `minidebian.local`, while `publishResult()` at `src/scannerwindow.cpp:1109-1112` retained `minidebian` because it replaces only `Unknown`.

- Observation: At the audited baseline, settings remained writable while worker threads read the same ordinary scalars and Qt containers; SCAN-CONFIGURATION has resolved that ownership defect.
  Evidence: `ScannerWindow::captureScanOptions()` now copies worker count, accuracy, MAC format, enabled services, adapter identity, retry/timeouts, and vendor data before launch, and every production worker-side policy read uses that const snapshot.

- Observation: Qt's implicitly shared sets and hashes preserve value-snapshot isolation when the source copy detaches during a concurrent mutation.
  Evidence: `scan_options_snapshot_isolation` repeatedly reads every field of the active copy before, during, and after changing the source preferences, and passes under ThreadSanitizer. This is foundational evidence, not yet the required production-window integration test.

- Observation: The repository has no tests, lint target, or continuous-integration workflow, while a strict build emits four warnings.
  Evidence: CTest reported zero tests and the audit recorded three narrowing conversions plus one shadowing warning.

- Observation: A completion callback can overtake queued progressive-result callbacks, so directly reconciling the worker's final list could still create a one-turn result dump even when ordinary arrivals were batched.
  Evidence: RESULT-SCALING now routes the authoritative final list through the same 64-row event-loop batches and ignores late progressive callbacks after completion reconciliation begins; the benchmark includes an unseen completion-only row.

- Observation: Rendering the offscreen 4,096-row GUI benchmark under ThreadSanitizer triggers races in Qt 6's uninstrumented font-rendering thread pool, while normal and strict-warning runs pass and the sanitizer traces contain no project-owned result-model frame.
  Evidence: the TSan failure originates in `QArrayData`, `QImageData`, and Qt pooled threads launched while the test window paints; the result model and presentation batching remain GUI-thread confined. This environmental sanitizer limitation is recorded rather than treated as a passing project concurrency check.

- Observation: A hidden target token must be admitted by both input validation and toolbar availability before its scan-path bypass is usable.
  Evidence: the first implementation recognized `test` inside `startScan()`, but the numeric-only target validator prevented typing it and the Scan action still depended on finding an adapter. The production GUI contract now exercises accepted input, adapter-free action availability, progressive completion, and cancellation.

- Observation: A ping-silent device with a valid unicast neighbor entry may remain in Linux `DELAY` for about five seconds before active confirmation promotes it to `REACHABLE`.
  Evidence: the reported field device rejected ping and common-port probes while moving from `STALE`/`DELAY` to `REACHABLE` only after repeated activity. The 0.4.3-to-0.4.4 diff contains no detection change; the row was absent from the authoritative worker result. A guarded single-target run through the repaired production `scanHosts` path recovered it from a stale starting state.

- Observation: The bundled vendor data has no durable source or redistribution record, but IEEE publishes persistent public CSV listings for 24-, 28-, and 36-bit assignments.
  Evidence: the existing `data/oui.txt` is an unexplained snapshot; the IEEE Registration Authority provides public MA-L, MA-M, and MA-S downloads.

- Observation: The GitHub repository is public, so keyless GitHub artifact and SBOM attestations are available without a long-lived signing secret.
  Evidence: `gh repo view calculatetech/open-ip-scanner` reports `visibility: PUBLIC`.

- Observation: The development environment has a running Avahi 0.8 daemon and Qt 6.10 D-Bus development support, but not the optional `avahi-client` and `avahi-common` pkg-config packages.
  Evidence: `systemctl is-active avahi-daemon` reports `active`, `qdbus6` successfully reads Avahi's version, and `pkg-config --modversion Qt6DBus` reports 6.10.2 while the Avahi C development packages are absent. The roadmap permits an equivalently cancellable backend, so `0.5.0` uses Avahi's installed system D-Bus API without per-host processes.

  Date/Author: 2026-07-13 / User and Codex

  Date/Author: 2026-07-14 / User and Codex

- Decision: Keep result rows value-only and place concise successful evidence provenance in the selected device's details pane; keep backend failures and health in diagnostics.
  Rationale: The table is an inventory rather than a device narrative. A compact aligned details list preserves accuracy and alternate evidence without expanding rows, service tags, or columns. ## Context and Orientation

`open-ip-scanner` is a C++17 Qt Widgets desktop application. `src/main.cpp` creates the application. `src/scannerwindow.h` declares the window, result types, worker helpers, and all mutable settings. `src/scannerwindow.cpp` builds the UI and performs every scan, resolver, process, socket, settings, vendor, export, and rendering operation. `CMakeLists.txt` defines a single executable and CPack package. `resources/` contains the icon, desktop entry, AppStream metadata, and Qt resources. `data/oui.txt` is the current embedded vendor assignment list.

`docs/production-readiness-audit.md` contains the evidence for the as-found defects. `docs/roadmap.md` is the only backlog and owns SCAN-CONFIGURATION through DNS-SD-DISCOVERY; only SCAN-CONFIGURATION through RELEASE-DOCS are required for 1.0. Do not create a second task list outside this ExecPlan's required Progress section. When an item is demonstrably complete, move its existing entry to the roadmap's Completed section without changing or duplicating its identifier.

A scan target is one IPv4 address on one selected network interface. A probe is a bounded attempt to gather one fact, such as ICMP reachability, a neighbor-cache entry, or a TCP connection. Enrichment is metadata gathered after or while the host is established, such as hostname, MAC vendor, or protocol evidence. mDNS is multicast Domain Name System on the local link; for 1.0 this project performs reverse-address-to-hostname resolution only. DNS-SD service browsing is related but out of scope.

The current scan launches blocking ping processes, reads neighbor state, opens sockets, runs one Avahi command per live host, falls back to synchronous `QHostInfo::fromName()`, and merges strings by IP. High and Maximum modes then retry missed hosts serially. Stop toggles an atomic flag but cannot abort active operations, and closing blocks the GUI thread waiting for completion.

The target state is Linux-specific. The new design keeps that honest: reusable models and algorithms live in `src/core/`; orchestration lives in `src/scan/`; Linux process, neighbor, Avahi, and network implementations live in `src/platform/linux/`; and Qt Widgets presentation lives in `src/ui/`. Tests mirror those directories under `tests/`.

## Plan of Work

Begin by refactoring the build without changing behavior. Raise the minimum CMake version to 3.28, require Qt 6.4 components Widgets, Network, Concurrent, PrintSupport, and Test, and require pkg-config. Create `ois_core`, `ois_scan`, `ois_linux`, and `ois_ui` targets with narrow public include directories. Keep the executable target name and installed binary `open-ip-scanner`. Add `CMakePresets.json` for `dev`, `release`, `asan-ubsan`, `tsan`, and `clang-tidy`; enable `CTest`; and add `tests/CMakeLists.txt`. Warning flags apply only to project sources and include `-Wall -Wextra -Wpedantic -Wconversion -Wsign-conversion -Wshadow -Wformat=2`; supported project warnings are errors. Add `.agent/test-results/` to `.gitignore` and create `scripts/quality-gate.sh` with `fast`, `full`, and `release` modes. The script never rewrites tracked files.

Create the stable core data model in `src/core/scantypes.h` and `src/core/scantypes.cpp`. The types and exact precedence rules are specified in Interfaces and Dependencies below. Register signal-crossing types with Qt's metatype system. No worker-facing type may contain QWidget, QSettings, or a pointer to mutable window state.

Move parsing to `src/core/targetparser.*`. Preserve single IP, full range, short range, CIDR, comma-separated input, deduplication, and the 4,096-target cumulative limit. A `/31` yields both endpoints and `/32` one endpoint; `/0` through `/19` automatic defaults become the adapter's local `/24`; `/20` through `/30` use usable subnet addresses. Auto Select uses the preferred adapter's bounded slice so one source address and route remain valid for every generated target; choosing a specific adapter regenerates the slice for that adapter. Report omitted addresses or adapters instead of producing invalid text. User-entered oversized ranges remain rejected with an exact count and remediation.

Move persistence to `src/core/settingsstore.*`. `AppSettings` is a plain value. `SettingsStore` accepts an injected QSettings-compatible storage location for tests. Schema 2 migrates each known schema-1 key explicitly, never calls `clear()`, treats a present empty `services/enabled_ids` as intentional, retains `-1` for per-toolbar-item inheritance, and validates custom vendor prefixes as exactly 6, 7, or 9 hexadecimal digits. On migration, retain history only when old `targets/remember_last` is true; otherwise delete `targets/history` and `targets/last_input`. Add `targets/history_enabled`, default false. UI writes go through a 300 ms single-shot debounce except explicit dialog acceptance and shutdown flush.

Move export to `src/core/csvexporter.*`. `CsvExportOptions` specifies all versus filtered rows and visible columns in visual order. The UI defaults to filtered rows and names the choice. Use QSaveFile and an explicit UTF-8 QTextStream encoding. Quote every cell, double embedded quotes, preserve line breaks, and prefix an apostrophe when the first character is `=`, `+`, `-`, `@`, tab, or carriage return. Commit only after checking stream status and QSaveFile commit; otherwise retain the old destination and display the concrete failure.

Replace `data/oui.txt` with `data/ieee/ma-l.csv.gz`, `ma-m.csv.gz`, and `ma-s.csv.gz`, plus `data/oui.tsv`, `data/oui-manifest.json`, and `data/README.md`. `tools/update_oui.py` downloads the three persistent IEEE CSV URLs to temporary files, validates headers and nonzero row counts, normalizes assignments, produces deterministic gzip files with timestamp zero, generates sorted UTF-8 TSV, records raw and generated SHA-256 values, retrieval UTC time, URLs, and row counts, and atomically replaces output only after every validation passes. `--offline` regenerates TSV and verifies the manifest from committed compressed inputs; builds and CI use this mode and never fetch. `OuiDatabase` loads the embedded TSV, applies custom 36-, 28-, then 24-bit prefixes before built-in prefixes of the same lengths, and exposes manifest date/hash. Reject zero, malformed, broadcast, and multicast addresses; report locally administered addresses as `Private / randomized` without assigning a vendor.

Create `src/scan/scansession.*` and `src/scan/scancontroller.*`. `ScannerWindow` validates targets and adapter, captures one `ScanOptions` value, and gives it to `ScanController`. The controller creates a QThread and moves a new `ScanSession` plus asynchronous Qt backends into it before starting. The session keeps at most `maxConcurrentTargets` host state machines active. Neighbor snapshot and local/gateway preliminary records happen once per scan. Every host flows through one discovery budget and, if alive, one enrichment budget; completed evidence is reused and never probed again in a reconciliation pass.

Accuracy profiles are fixed data, not scattered functions. Fast allows one 1,000 ms ping and one 350 ms service attempt. Balanced allows two 1,000 ms pings and two 750 ms service attempts. High allows three 2,000 ms pings and three 1,250 ms service attempts. Maximum allows four 3,000 ms pings and four 2,000 ms service attempts. The per-target safety ceiling is the greater of the profile minimum and the time required for every enabled service attempt plus all ping attempts and a two-second neighbor/enrichment reserve; with the four default services the profile minimums are five, eleven, twenty-five, and fifty seconds. Neighbor snapshot evidence is available to every profile. Enabled service ports are probed concurrently within the host budget, subject to a global socket limit of four times `maxConcurrentTargets`. Before launch, compute `ceil(targetCount / concurrency) * targetDeadline`; if it exceeds ten minutes, explain the worst-case safety estimate and require explicit confirmation. The estimate is a ceiling, not a prediction that every host consumes its deadline.
