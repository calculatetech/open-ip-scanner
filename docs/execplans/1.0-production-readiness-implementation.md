This ExecPlan is a living document. The sections `Progress`, `Surprises & Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must be kept up to date as work proceeds.

This plan is maintained in accordance with `.agent/PLANS.md` from the repository root. A contributor must be able to resume from this file and the working tree alone. Keep the plan self-contained, update it at every material stopping point, and replace the single revision note at the bottom when the plan changes.

## Purpose / Big Picture

Open IP Scanner 0.2.0 builds and can scan a local IPv4 network, but the production-readiness audit found unsafe worker ownership, unbounded cancellation, unreliable mDNS enrichment, misleading service evidence, no automated quality gate, and invalid release packaging. The goal of this plan is to turn that prototype into a dependable 1.0 desktop application for Linux x86-64 and IPv4 networks.

After this work, a user can select an adapter, scan as many as 4,096 IPv4 targets, stop or close without a frozen window, see where hostnames and service claims came from, obtain an Avahi `.local` reverse name when one is available on the selected interface, and export results without spreadsheet-injection or silent write failures. A maintainer can build and test the application from a clean checkout with one command, produce a policy-clean and hardened Debian-family package, and verify its software bill of materials and signed GitHub provenance.

The visible demonstration is a controlled scan fixture that publishes `fixture.local` through Avahi on a private test interface. The completed application must show that hostname with mDNS provenance, cancel the scan in less than two seconds, preserve a responsive 4,096-row table, and pass the full release gate described below.

## Surprises & Discoveries

- Observation: Almost all behavior currently lives in a 3,534-line `ScannerWindow` implementation, including parsing, scheduling, process execution, networking, persistence, export, and rendering.
  Evidence: `src/scannerwindow.cpp` and `src/scannerwindow.h` contain the entire scan path and UI state; CMake builds only one executable.

- Observation: The current application successfully invokes Avahi and receives the local `.local` answer, but an earlier preliminary hostname prevents the better answer from replacing it.
  Evidence: The audit trace captured `avahi-resolve-address -4 10.10.30.34` writing `minidebian.local`, while `publishResult()` at `src/scannerwindow.cpp:1109-1112` retained `minidebian` because it replaces only `Unknown`.

- Observation: At the audited baseline, settings remained writable while worker threads read the same ordinary scalars and Qt containers; SCAN-CONFIGURATION has resolved that ownership defect.
  Evidence: `ScannerWindow::captureScanOptions()` now copies worker count, accuracy, MAC format, enabled services, adapter identity, retry/timeouts, and vendor data before launch, and every production worker-side policy read uses that const snapshot.

- Observation: Qt's implicitly shared sets and hashes preserve value-snapshot isolation when the source copy detaches during a concurrent mutation.
  Evidence: `scan_options_snapshot_isolation` repeatedly reads every field of the active copy before, during, and after changing the source preferences, and passes under ThreadSanitizer. This is foundational evidence, not yet the required production-window integration test.

- Observation: The repository has no tests, lint target, or continuous-integration workflow, while a strict build emits four warnings.
  Evidence: CTest reported zero tests and the audit recorded three narrowing conversions plus one shadowing warning.

- Observation: The bundled vendor data has no durable source or redistribution record, but IEEE publishes persistent public CSV listings for 24-, 28-, and 36-bit assignments.
  Evidence: the existing `data/oui.txt` is an unexplained snapshot; the IEEE Registration Authority provides public MA-L, MA-M, and MA-S downloads.

- Observation: The GitHub repository is public, so keyless GitHub artifact and SBOM attestations are available without a long-lived signing secret.
  Evidence: `gh repo view calculatetech/open-ip-scanner` reports `visibility: PUBLIC`.

## Decision Log

- Decision: Version 1.0 supports Linux x86-64 and IPv4 only. Ubuntu 24.04 with Qt 6.4.2, GCC 13, and CMake 3.28 is the compatibility floor; Debian 13 is the newer CI environment; Kubuntu 26.04 receives a real-desktop release-candidate smoke test.
  Rationale: Ubuntu 24.04 has the older package versions among the requested environments. Testing that baseline plus Debian 13 covers development on Debian 13 and Kubuntu 26.04 without preserving unsupported Qt 5 or Windows claims.
  Date/Author: 2026-07-13 / User and Codex

- Decision: Keep C++17, require Qt 6.4 or newer, and remove the Qt 5 fallback.
  Rationale: C++17 is sufficient for the design, Qt 6.4 is available on the compatibility floor, and the current non-Linux and Qt 5 claims have no functional or test coverage.
  Date/Author: 2026-07-13 / Codex

- Decision: Make mDNS reverse-hostname enrichment a required 1.0 capability and link directly to Avahi client libraries.
  Rationale: The roadmap requires reliable, observable mDNS. A direct client supplies interface identity, lifecycle callbacks, and cancellable resolver handles that the current subprocess cannot provide. Full DNS-SD browsing remains post-1.0.
  Date/Author: 2026-07-13 / User and Codex

- Decision: Use a single asynchronous `ScanSession` on a dedicated Qt event-loop thread instead of nested `QtConcurrent` workers and blocking waits.
  Rationale: QProcess, Qt sockets, timers, and QHostInfo all have cancellable asynchronous APIs. One ownership thread makes deadlines, cleanup, and tests deterministic and eliminates worker reads of UI-owned state.
  Date/Author: 2026-07-13 / Codex

- Decision: Identity is the pair of selected interface index and IPv4 address, never the address alone.
  Rationale: The same private address can exist on overlapping links or VPNs. Interface-aware identity is also required to validate Avahi answers and neighbor entries.
  Date/Author: 2026-07-13 / Codex

- Decision: Replace the bundled vendor dump with a reproducible embedded snapshot derived from the persistent IEEE MA-L, MA-M, and MA-S public CSV downloads.
  Rationale: A system `ieee-data` dependency and its paths are distribution-specific. A committed verified snapshot keeps vendor lookup available on every supported installation while recording provenance and avoiding network access during builds.
  Date/Author: 2026-07-13 / User and Codex

- Decision: Target history is disabled by default and legacy stored history is deleted during the schema-2 privacy migration unless the old remember-last option was explicitly enabled.
  Rationale: Target ranges can reveal internal network structure. Privacy should be the clean-install and migration default, while an explicit old retention choice is preserved.
  Date/Author: 2026-07-13 / Codex

- Decision: TCP connection proves an open port, not a service. Only bounded protocol-specific evidence upgrades a probable label to verified.
  Rationale: Port numbers are conventions. Separating reachability from protocol evidence prevents false service and operating-system claims.
  Date/Author: 2026-07-13 / Codex

- Decision: Release artifacts use GitHub's keyless Sigstore-backed provenance and SBOM attestations rather than a maintained GPG secret.
  Rationale: The repository is public, GitHub attestations are verifiable against repository identity, and keyless signing avoids secret distribution and rotation.
  Date/Author: 2026-07-13 / User and Codex

- Decision: No commit, push, branch-protection change, tag, GitHub release, or package publication is implied by implementing this ExecPlan.
  Rationale: Those are separate publication actions. If a commit is later authorized, meaningful code must receive one fresh read-only adversarial review after validation and before that commit; fixes are not recursively reviewed.
  Date/Author: 2026-07-13 / Codex

- Decision: Replace numeric roadmap identifiers with concise domain identifiers such as SCAN-CONFIGURATION, MDNS-RESOLVER, and DEBIAN-PACKAGING while retaining stable descriptive anchors.
  Rationale: Contributors can understand and cite a milestone without looking up an arbitrary sequence number. The user explicitly requested human-sensible milestone names.
  Date/Author: 2026-07-13 / User and Codex

- Decision: Implement SCAN-CONFIGURATION before the ExecPlan's larger scan-engine milestone, without pulling cancellation or scheduling redesign into scope.
  Rationale: A const value snapshot closes the current settings race independently and creates the ownership boundary needed by the later ScanSession design.
  Date/Author: 2026-07-13 / User and Codex

## Context and Orientation

`open-ip-scanner` is a C++17 Qt Widgets desktop application. `src/main.cpp` creates the application. `src/scannerwindow.h` declares the window, result types, worker helpers, and all mutable settings. `src/scannerwindow.cpp` builds the UI and performs every scan, resolver, process, socket, settings, vendor, export, and rendering operation. `CMakeLists.txt` defines a single executable and CPack package. `resources/` contains the icon, desktop entry, AppStream metadata, and Qt resources. `data/oui.txt` is the current embedded vendor assignment list.

`docs/production-readiness-audit.md` contains the evidence for the as-found defects. `docs/roadmap.md` is the only backlog and owns SCAN-CONFIGURATION through DNS-SD-DISCOVERY; only SCAN-CONFIGURATION through RELEASE-DOCS are required for 1.0. Do not create a second task list outside this ExecPlan's required Progress section. When an item is demonstrably complete, move its existing entry to the roadmap's Completed section without changing or duplicating its identifier.

A scan target is one IPv4 address on one selected network interface. A probe is a bounded attempt to gather one fact, such as ICMP reachability, a neighbor-cache entry, or a TCP connection. Enrichment is metadata gathered after or while the host is established, such as hostname, MAC vendor, or protocol evidence. mDNS is multicast Domain Name System on the local link; for 1.0 this project performs reverse-address-to-hostname resolution only. DNS-SD service browsing is related but out of scope.

The current scan launches blocking ping processes, reads neighbor state, opens sockets, runs one Avahi command per live host, falls back to synchronous `QHostInfo::fromName()`, and merges strings by IP. High and Maximum modes then retry missed hosts serially. Stop toggles an atomic flag but cannot abort active operations, and closing blocks the GUI thread waiting for completion.

The target state is Linux-specific. The new design keeps that honest: reusable models and algorithms live in `src/core/`; orchestration lives in `src/scan/`; Linux process, neighbor, Avahi, and network implementations live in `src/platform/linux/`; and Qt Widgets presentation lives in `src/ui/`. Tests mirror those directories under `tests/`.

## Plan of Work

Begin by refactoring the build without changing behavior. Raise the minimum CMake version to 3.28, require Qt 6.4 components Widgets, Network, Concurrent, PrintSupport, and Test, and require pkg-config. Create `ois_core`, `ois_scan`, `ois_linux`, and `ois_ui` targets with narrow public include directories. Keep the executable target name and installed binary `open-ip-scanner`. Add `CMakePresets.json` for `dev`, `release`, `asan-ubsan`, `tsan`, and `clang-tidy`; enable `CTest`; and add `tests/CMakeLists.txt`. Warning flags apply only to project sources and include `-Wall -Wextra -Wpedantic -Wconversion -Wsign-conversion -Wshadow -Wformat=2`; supported project warnings are errors. Add `.agent/test-results/` to `.gitignore` and create `scripts/quality-gate.sh` with `fast`, `full`, and `release` modes. The script never rewrites tracked files.

Create the stable core data model in `src/core/scantypes.h` and `src/core/scantypes.cpp`. The types and exact precedence rules are specified in Interfaces and Dependencies below. Register signal-crossing types with Qt's metatype system. No worker-facing type may contain QWidget, QSettings, or a pointer to mutable window state.

Move parsing to `src/core/targetparser.*`. Preserve single IP, full range, short range, CIDR, comma-separated input, deduplication, and the 4,096-target cumulative limit. A `/31` yields both endpoints and `/32` one endpoint; `/0` through `/19` automatic defaults become the adapter's local `/24`; `/20` through `/30` use usable subnet addresses. Auto Select adds adapter slices in current priority order until 4,096 unique targets and reports omitted adapters instead of producing invalid text. User-entered oversized ranges remain rejected with an exact count and remediation.

Move persistence to `src/core/settingsstore.*`. `AppSettings` is a plain value. `SettingsStore` accepts an injected QSettings-compatible storage location for tests. Schema 2 migrates each known schema-1 key explicitly, never calls `clear()`, treats a present empty `services/enabled_ids` as intentional, retains `-1` for per-toolbar-item inheritance, and validates custom vendor prefixes as exactly 6, 7, or 9 hexadecimal digits. On migration, retain history only when old `targets/remember_last` is true; otherwise delete `targets/history` and `targets/last_input`. Add `targets/history_enabled`, default false. UI writes go through a 300 ms single-shot debounce except explicit dialog acceptance and shutdown flush.

Move export to `src/core/csvexporter.*`. `CsvExportOptions` specifies all versus filtered rows and visible columns in visual order. The UI defaults to filtered rows and names the choice. Use QSaveFile and an explicit UTF-8 QTextStream encoding. Quote every cell, double embedded quotes, preserve line breaks, and prefix an apostrophe when the first character is `=`, `+`, `-`, `@`, tab, or carriage return. Commit only after checking stream status and QSaveFile commit; otherwise retain the old destination and display the concrete failure.

Replace `data/oui.txt` with `data/ieee/ma-l.csv.gz`, `ma-m.csv.gz`, and `ma-s.csv.gz`, plus `data/oui.tsv`, `data/oui-manifest.json`, and `data/README.md`. `tools/update_oui.py` downloads the three persistent IEEE CSV URLs to temporary files, validates headers and nonzero row counts, normalizes assignments, produces deterministic gzip files with timestamp zero, generates sorted UTF-8 TSV, records raw and generated SHA-256 values, retrieval UTC time, URLs, and row counts, and atomically replaces output only after every validation passes. `--offline` regenerates TSV and verifies the manifest from committed compressed inputs; builds and CI use this mode and never fetch. `OuiDatabase` loads the embedded TSV, applies custom 36-, 28-, then 24-bit prefixes before built-in prefixes of the same lengths, and exposes manifest date/hash. Reject zero, malformed, broadcast, and multicast addresses; report locally administered addresses as `Private / randomized` without assigning a vendor.

Create `src/scan/scansession.*` and `src/scan/scancontroller.*`. `ScannerWindow` validates targets and adapter, captures one `ScanOptions` value, and gives it to `ScanController`. The controller creates a QThread and moves a new `ScanSession` plus asynchronous Qt backends into it before starting. The session keeps at most `maxConcurrentTargets` host state machines active. Neighbor snapshot and local/gateway preliminary records happen once per scan. Every host flows through one discovery budget and, if alive, one enrichment budget; completed evidence is reused and never probed again in a reconciliation pass.

Accuracy profiles are fixed data, not scattered functions. Fast allows one 750 ms ping and a one-second target deadline with no TCP discovery. Balanced allows one 1,000 ms ping and a two-second deadline with no TCP discovery. High allows two 1,000 ms ping attempts plus one concurrent 300 ms TCP discovery wave and a four-second deadline. Maximum allows two 1,500 ms ping attempts plus two concurrent 600 ms TCP waves and an eight-second deadline. Neighbor snapshot evidence is available to every profile. Enabled service ports are probed concurrently within the host budget, subject to a global socket limit of four times `maxConcurrentTargets`. Before launch, compute `ceil(targetCount / concurrency) * targetDeadline`; if it exceeds ten minutes, show the estimate and require explicit confirmation. The estimate is an upper bound, not a promise that every host consumes its deadline.

Implement Linux process and neighbor support in `src/platform/linux/`. `QtProcessRunner` owns QProcess instances by request ID, uses program plus argument arrays without a shell, captures at most 4 KiB of stderr, and maps missing executable, start failure, timeout, abnormal exit, and nonzero exit separately. Cancellation terminates, waits at most 100 ms asynchronously, then kills. `LinuxNeighborProvider` runs `ip -j neigh show dev <interface>`, parses JSON, validates interface and unicast MAC, and maps NUD state. REACHABLE, DELAY, PROBE, and PERMANENT can establish liveness; STALE supplies MAC metadata only after another method establishes liveness; INCOMPLETE, FAILED, NONE, NOARP, zero, multicast, broadcast, and malformed entries establish nothing.

Use asynchronous QTcpSocket/QSslSocket in `QtNetworkProbeBackend`. Bind every socket to the selected local IPv4 before connecting. A connection produces `OpenPort`. HTTP is verified only by an HTTP status line after a bounded HEAD request. HTTPS is verified by a completed TLS handshake; local certificate errors are recorded and may be ignored for protocol identification but are never described as trusted. SSH requires a banner beginning `SSH-`; FTP and SMTP require a valid 220 greeting with the expected protocol token. RDP, SMB, and Telnet remain probable open-port labels until a real verifier exists. Do not infer an operating system from a banner. Details traffic occurs only when the details pane is visible and the user selects a host; cache it for that current record and invalidate derived display when evidence changes.

Implement `AvahiHostnameResolver` in `src/platform/linux/avahihostnameresolver.*`. CMake requires `avahi-client` and `avahi-common` through pkg-config. One resolver instance creates one AvahiThreadedPoll and AvahiClient for the scan. For each unique TargetKey, call `avahi_address_resolver_new(client, interfaceIndex, AVAHI_PROTO_INET, address, AVAHI_LOOKUP_USE_MULTICAST, callback, context)`. Verify callback interface, protocol, and address before accepting the trimmed hostname. Use a two-second QTimer deadline. Share callbacks for duplicate requests, cache outcomes only until the session ends, and free each AvahiAddressResolver exactly once. On cancellation, lock the threaded poll, free outstanding resolvers, unlock, stop the poll from outside its helper thread, and publish Cancelled once. Client construction failure, daemon unavailable, resolver allocation failure, no record, wrong interface, timeout, malformed name, and cancellation have distinct outcomes. Post Avahi callbacks to the ScanSession thread with queued QMetaObject invocation; never touch Qt UI from the Avahi helper thread.

Implement `SystemHostnameResolver` with QHostInfo::lookupHost and QHostInfo::abortHostLookup. Invoke it only after Avahi returns no usable record, not after cancellation. Store its provenance as SystemResolver because the host name-service configuration may consult files, mDNS modules, or unicast DNS. Apply hostname quality in one merge function: AvahiMdns quality 400, SystemResolver 300, LocalHost 200, PreliminaryGateway 100, Unknown 0. Higher quality replaces lower; equal quality keeps the first stable nonempty value. The same local self fixture must therefore upgrade `minidebian` to `minidebian.local`.

Create `src/core/diagnostics.*`. A DiagnosticEvent contains timestamp, severity, stable code, stage, remediation, and bounded message; it does not contain target address, hostname, target history, raw response, or banner by default. Keep a 500-event in-memory ring. Diagnostics UI shows capability state and counts by code. Logging is opt-in and writes through a rotating sink under QStandardPaths::AppLocalDataLocation with three one-MiB files. Support export is JSON containing application/build/platform versions, selected capability booleans, aggregate counts, and redacted events. Tests assert forbidden strings never appear.

Replace the table with `src/ui/devicetablemodel.*`, `devicefiltermodel.*`, and `servicedelegate.*`. The model is keyed by TargetKey and stores DeviceRecord values. Apply queued changes in batches of at most 100 records or every 16 ms. The proxy sorts IP numerically, MAC numerically when valid, hostname/vendor locale-aware, and services by normalized protocol/port data; it filters actual model roles rather than rendered text. The delegate paints service chips and handles clicks without persistent cell widgets. Preserve selection by TargetKey. Never rebuild final results through incremental insertion.

Update `ScannerWindow` to coordinate these services and remove extracted code. Settings remain editable during a scan because the current session uses an immutable snapshot; the UI states that changes apply to the next scan. Stop calls ScanController::cancel. `closeEvent()` ignores the first close while a scan is active, disables the window, shows `Stopping scan…`, requests cancellation, and closes through a queued callback after `finished`; it never calls waitForFinished. Production backends must finish cancellation within two seconds. A two-second UI watchdog reports an internal shutdown error but does not destroy a live QThread; this is a test failure and release blocker rather than an unsafe forced termination.

Add a first-scan authorization dialog keyed by `safety/authorization_ack_version = 1`. It states that scanning must be authorized and lists the active discovery and enrichment traffic. The main window shows a concise live summary such as `Balanced: ICMP + neighbor cache; service checks after discovery; mDNS and system hostname lookup`. Settings add Save target history, Remember last target, Clear history, and Enable diagnostic log controls. Remember last target is disabled unless history retention is enabled.

Remove the environment-variable high-DPI override or replace it with the supported static API before QApplication construction, choosing the warning-free behavior on Qt 6.4 and 6.8. Give every icon-only action an accessible name, description, tooltip, shortcut, and focus policy. Use palette roles rather than fixed selection colors; derive service-chip foreground/background for contrast. Wrap dense settings pages in QScrollArea. Keep strings in source for 1.0 because localization is post-1.0, but avoid layouts that prevent future translation.

## Idempotence and Recovery

Builds use ignored `build-*` directories and can be deleted/reconfigured without touching tracked source. Quality scripts use disposable staging roots and containers. OUI updates download to temporary files and replace tracked outputs only after validation; interruption leaves the previous verified snapshot intact. QSettings tests always use temporary INI files, never the developer profile. Avahi integration uses a disposable private container and dummy interface.

Refactors should be additive before subtractive: introduce tested core types and adapters, route one existing call path through them, then remove old helpers only after equivalence tests pass. If a milestone breaks behavior, keep the last passing implementation reachable in the working tree while fixing the new path; do not add a permanent feature flag or ship parallel scan engines.
