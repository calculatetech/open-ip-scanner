## Purpose / Big Picture

The project needs an evidence-backed assessment of everything that prevents a dependable 1.0 release, with special attention to whether Avahi actually contributes multicast Domain Name System (mDNS) data to discovered devices. At the end of this work, a maintainer can read one prioritized report, reproduce the important observations, understand which findings are proven versus environment-dependent, and use the repository roadmap as the source of truth for remaining release work.

The visible outcome is a Markdown audit in `docs/` that connects each finding to concrete source locations or command output. It will state whether the current Avahi path can enrich devices, identify the likely failure modes, and rank release blockers separately from lower-priority hardening work.

## Surprises & Discoveries

- Observation: The repository predates its ExecPlan policy and had no `docs/` directory when this audit began.
  Evidence: `rg --files` initially listed only root documentation, `data/`, `resources/`, and `src/`; `docs/execplans/` was created for this plan.

- Observation: The implemented Avahi feature is a silent, per-address reverse lookup for already-discovered IPv4 hosts, not mDNS/DNS-SD discovery or advertised-service enrichment.
  Evidence: `src/scannerwindow.cpp:1436-1470` invokes only `avahi-resolve-address -4`; the repository contains no `avahi-browse` call, and `src/scannerwindow.cpp:1506-1547` derives services solely from fixed TCP ports.

- Observation: The application does execute Avahi for the local address, but an earlier non-`Unknown` self hostname prevents the better `.local` result from replacing it.
  Evidence: A disposable harness displayed `minidebian`; input/output `strace` captured `/usr/bin/avahi-resolve-address -4 10.10.30.34` writing `10.10.30.34\tminidebian.local\n` and exiting successfully; `publishResult()` at `src/scannerwindow.cpp:1109-1112` replaces only an `Unknown` hostname.

- Observation: The project builds successfully but defines no tests or lint target, and strict compiler warnings are not clean.
  Evidence: Debug and Release builds linked successfully; CTest reported `Total Tests: 0`; the target list contained no lint target; a manual strict-warning build emitted four warnings.

- Observation: The generated Debian package is installable in structure but fails basic distribution-quality checks.
  Evidence: Lintian emitted five errors, twelve warnings, and one informational hardening issue; AppStream validation exited 3 with two warnings and two informational omissions.

- Observation: Scan settings remain mutable while scan threads read the same ordinary C++ and Qt values without synchronization.
  Evidence: `showSettingsDialog()` remains reachable during a scan and writes `maxParallelProbes_`, `accuracyLevel_`, `macDisplayFormat_`, `enabledServiceIds_`, and `customOuiVendors_` at `src/scannerwindow.cpp:2805-2855`, while scan paths read them at `1168`, `1177-1234`, `1404-1413`, `1522-1547`, and `1598-1633`.

## Context and Orientation

`open-ip-scanner` is a small C++ desktop application built with CMake and Qt. `src/main.cpp` starts the graphical application. `src/scannerwindow.h` and `src/scannerwindow.cpp` contain the window, network scan, device enrichment, and export behavior. `CMakeLists.txt` defines dependencies, compilation, installation, packaging, and tests if any. `resources/` contains the icon and Linux desktop/AppStream metadata. `data/oui.txt` supplies organizational prefixes used to map a Media Access Control (MAC) address to a hardware vendor. Root files such as `README.md` and `CHANGELOG.md` describe the intended behavior and release history.

mDNS is a local-network naming protocol that resolves names ending in `.local` without a central Domain Name System server. Avahi is the common Linux service and command-line tooling that implements mDNS. Device enrichment means attaching useful metadata, such as a human-readable host name or advertised service, to an Internet Protocol (IP) address found by the scanner. The audit must distinguish an implementation defect from a machine or network on which Avahi is absent, blocked, or has nothing to discover.

DNS-Based Service Discovery (DNS-SD) is a related but separate operation that browses advertised service instances and reads their host, port, and metadata records. The current repository promises mDNS hostname resolution, not DNS-SD browsing. `QHostInfo::fromName()` is described in the audit as the synchronous system resolver because the operating system may consult files, mDNS name-service modules, or unicast DNS; the application does not control or identify that source.

The user-added `.agent/PLANS.md` was untracked before this work and belongs to the user. It must not be rewritten as part of the audit. There were no pre-existing application changes in `git status --short` at the initial inventory.

In `build-audit/probe/main.cpp`, place this local-address-only driver:

    #include <QApplication>
    #include <QLabel>
    #include <QLineEdit>
    #include <QTableWidget>
    #include <QTextStream>
    #include <QTimer>

    #include "scannerwindow.h"

    int main(int argc, char **argv)
    {
        QApplication app(argc, argv);
        if (argc != 2) {
            QTextStream(stderr) << "usage: audit-probe <local-ip>\n";
            return 2;
        }

        ScannerWindow window;
        window.show();

        QLineEdit *targets = nullptr;
        for (QLineEdit *edit : window.findChildren<QLineEdit *>()) {
            if (edit->placeholderText().startsWith("Examples:")) {
                targets = edit;
                break;
            }
        }
        if (targets == nullptr) {
            QTextStream(stderr) << "target input not found\n";
            return 3;
        }
        targets->setText(QString::fromLocal8Bit(argv[1]));

        auto *poll = new QTimer(&window);
        poll->setInterval(25);
        QObject::connect(poll, &QTimer::timeout, &window, [&]() {
            for (QLabel *label : window.findChildren<QLabel *>()) {
                if (!label->text().startsWith("Scan complete.")) {
                    continue;
                }
                QTableWidget *table = window.findChild<QTableWidget *>();
                QTextStream out(stdout);
                out << label->text() << "\n";
                out << "rows=" << (table ? table->rowCount() : -1) << "\n";
                if (table != nullptr && table->rowCount() > 0) {
                    for (int col = 0; col < 4; ++col) {
                        out << (table->item(0, col)
                                    ? table->item(0, col)->text()
                                    : QString("<null>"))
                            << "\n";
                    }
                }
                out.flush();
                app.exit(0);
                return;
            }
        });

        QTimer::singleShot(0, &window, [&]() {
            if (!QMetaObject::invokeMethod(&window, "startScan", Qt::DirectConnection)) {
                QTextStream(stderr) << "startScan invocation failed\n";
                app.exit(4);
                return;
            }
            poll->start();
        });
        QTimer::singleShot(20000, &window, [&]() {
            QTextStream(stderr) << "self-scan timed out\n";
            app.exit(5);
        });

        return app.exec();
    }

## Validation and Acceptance
